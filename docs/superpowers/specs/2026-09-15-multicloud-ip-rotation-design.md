已确认要求：

- 列出 AWS API 可访问的实例，由用户勾选允许管理的实例；未勾选和新发现实例只读。
- DNS A/AAAA 分别绑定受管实例的 IPv4/IPv6 地址来源。
- IPv4、IPv6 自动轮换分别设开关；关闭不影响监测与告警。
- Agent 使用 Go，主动拉取任务并上报 TCP、HTTP/HTTPS 结果，不实现 ICMP。

- 每次故障最多轮换次数、轮换间隔可配置；达到上限暂停自动轮换，继续监测并告警。
- AWS 优先通过 API 直接换址。允许停止再启动实例是独立、默认关闭的实例级开关。
- 在配置次数内重复换址与复测，新地址通过检查后更新关联 DNS。

本期不包含实例创建/删除、远程执行命令、自动更改安全组或防火墙、自动升级网络套餐、迁移子网、整体后端 Go 重写、探测 Agent 执行云 API。

## 3. 云账号、清单与授权

### 3.1 账号接入

AWS 接入提供两类凭证来源：加密保存的专用 IAM AccessKey，或部署环境身份配合可选 AssumeRole。第一期不要求用户提供 root 凭证。凭证验证后记录 AWS account ID，任何密钥均不回显、不发给 Agent。

账号同步默认发现该账号已经启用且可访问的区域，支持限制区域范围；不自动启用 AWS 区域。各区域独立分页、独立记录完成/错误状态，权限不足不能展示成空清单。只有完整成功的区域扫描才能判定资源消失。

展示实例名称、服务类型、区域/可用区、远端 ID、运行状态、网卡、IPv4/IPv6、管理状态和换址能力。资源唯一身份包含账号、服务、区域和远端 ID，不能仅使用实例名称。

### 3.2 管理授权

管理授权绑定具体实例身份，新增实例默认只读。普通用户只能授权自己账号的实例，管理员跨用户操作沿用现有审计规则。

所有人工和后台云写操作在执行前重新检查账号启用状态、实例授权、地址范围和策略版本。取消授权后不再启动新的变更步骤；正在飞行中的 AWS 请求无法撤销，读取其最终结果、记录实际状态，并暂停后续写操作。界面展示尚未完成的 DNS 发布和清理项目。

云 API 的读取权限与写入权限分开报告。能力状态使用可用、受限、未知；未知不能自动开启轮换。权限检查不能通过随意修改实例来证明可写。

## 4. 多云接口与地址模型

适配器提供以下逻辑操作：验证身份、列出作用域、分页发现实例、读取网络资源、评估地址能力、生成轮换步骤、执行单步、观察远端结果、清理明确归属的地址资源。

不强制所有厂商实现一个不可观察的 `rotateIP()`。每种方式声明地址族、是否需要停机、是否释放原地址、是否支持恢复、是否需要客体系统配置，以及异步等待条件。

地址来源保存云账号、实例、网卡/附着点、地址族、地址角色/槽位。具体 IP、厂商 allocation ID、地址段及 prefix length 是其当前版本的属性。DNS 始终发布单个有效主机地址，不能把 IPv6 地址段直接写入 AAAA。

每个受管地址槽位只能有一个轮换策略；同一实例可以有多个槽位，但它们共用实例级变更锁。同一地址可以被多个 Pool 节点引用，所有引用消费同一地址版本，不能独立轮换。

新增 `cloud` 节点地址来源，与 `static`、`ddns` 互斥。云地址不能被 DDNS 心跳覆盖。已有节点和策略迁移后保持原行为。

## 5. AWS 换址方式

| 资源 | 首期方式 | 能力限制 |
| --- | --- | --- |
| EC2 自动公网 IPv4 | 使用网卡公网 IPv4 属性关闭/开启，逐步读取验证 | 仅支持符合 AWS 限制的主要网卡与网络配置；不保证申请到从未使用过的地址 |
| EC2 EIP | AllocateAddress → AssociateAddress → 验证 → 按清理策略 ReleaseAddress | 保留 allocation/association ID；不得抢占其他实例的地址；原 EIP 解绑不等于释放 |
| EC2 IPv6 | 分配新的可管理 IPv6 → 等待目标可用 → 复测/发布 → 按授权解绑旧地址 | 受子网范围、网卡容量和客体系统配置限制；被标记为 primary 的 IPv6 不能普通解绑，不列为可直接轮换槽位 |
| Lightsail IPv4 | AllocateStaticIp → 必要时 DetachStaticIp → AttachStaticIp → 验证/发布/清理 | 动态 IPv4 可在显式接管时转为静态 IP 管理；需要可用配额，避免无限累积静态 IP |
| Lightsail IPv6 | 对符合条件的双栈实例执行 SetIpAddressType：ipv4 → dualstack，等待每一步完成并读取地址 | 会释放旧 IPv6；不保证恢复旧地址；不自动改变 IPv6-only 套餐，不使用 accept-bundle-update 改套餐 |

使用新地址前验证确实发生了预期变化。如果厂商返回本次事件已经失败的地址，不把它当作成功，也不无界循环申请。

停止/启动仅可作为用户明确启用且适配器确认适用的特定方式，例如符合条件的 EC2 动态公网 IPv4。权限、配额、限流、探测不足不触发停机降级。EIP 和 IPv6 不因为启用停机开关就被假定能靠重启更换。

AWS 操作成功仅说明控制面变更完成。IPv6 还依赖实例操作系统实际启用地址、业务监听、防火墙和路由。外部 Agent 负责验证业务可达；平台不自动 SSH 到实例修改网络。

更换同一 IPv6 子网内的地址不代表更换网络前缀，也不能保证解决整个前缀的不可达问题。

## 6. DNS 绑定与已有 Pool 的关系

DNS 页面增加地址来源选择：手工、现有 Pool、云实例。选择云实例时分别为 A/AAAA 选择地址槽位，展示所有受影响记录、当前地址和已验证地址。

直接绑定云实例使用现有 Pool/Endpoint/DomainBinding 模型承载，可创建单节点 Pool 并在界面简化配置。已有 Pool 可以增加 cloud 节点。每个 zone/fqdn/type 仍只有一个管理者；已有受管记录必须明确转换绑定，不能再并列添加第二个写入流程。

轮换策略的权威探测配置属于地址槽位，可复用 Pool/节点检查定义；域名自定义业务检查继续影响自身 Pool 故障转移，但不在未经选择时直接触发共享云 IP 轮换。多个域名使用同一 IP 时只生成一次换址事件。

外部结果只提升相同地址版本的候选值。新地址验证通过后，现有协调器为引用该地址的节点重新计算期望状态，只有策略当前选择该节点的记录才发布其新地址。备用节点地址更新不强行抢占活动节点。

所有 DNS 写入走现有 Operation、远端读取验证与漂移修复。跨厂商/跨记录不保证原子性，成功项保留；失败项独立重试，不因 DNS 失败重新换云 IP。

候选未通过时不发布该地址，也不默认删除 DNS。界面必须分别展示云端实际地址、最后通过探测的地址和实际已发布值：云端已经解绑或释放旧地址时，保留旧 DNS 不代表业务仍然可用。

## 7. 外部 Go Agent

### 7.1 安装与身份

控制台创建探测点，生成有期限的一次性安装 Token，兑换后只保存节点专用运行 Token 的哈希。支持吊销与重新注册，探测身份与 DDNS 身份完全分开。

提供 Linux amd64/arm64 安装脚本和 systemd 服务，并交叉编译 Windows、macOS amd64/arm64 命令行程序。第一期 Linux 提供服务安装、状态、更新、卸载；其他平台提供前台运行与配置说明。更新校验发布产物完整性，不自动执行未知来源脚本。

Agent 无需入站监听，HTTPS 出站拉取任务和上报结果。Token 仅允许访问自己的任务；不允许访问云凭证、DNS 管理或其他用户资源。可同机部署 DDNS Agent，但不合并权限。

### 7.2 探测行为

支持 TCP 连接和 HTTP/HTTPS GET/HEAD，复用现有超时、状态码、正文包含/正则、请求头、重定向、Host/SNI 与 TLS 验证配置。明确指定 tcp4/tcp6 或等价连接方式，不能失败后自动改用另一地址族。

探测连接目标 IP，HTTP Host/TLS SNI 使用配置的域名；不因域名仍解析到旧 IP 而测错地址。IPv6 URL 使用正确方括号表示。重定向保持受控的目标规则，不允许变成任意地址探测。

Agent 声明 IPv4/IPv6 能力；地址族不可用报告 unavailable，不能伪装成目标失败。任务默认仅允许公共单播目标，拒绝回环、链路本地、云元数据地址等；私网探测需要探测点本地配置和平台配置同时允许指定范围。

Go 正则使用 RE2 语义，现有 JS 正则不保证全部兼容。新增配置保存时标注所用执行器，外部探测使用共享兼容子集校验；不兼容配置明确拒绝，不能悄悄变成探测失败。

### 7.3 拉取协议与结果可靠性

版本化 HTTPS API 包括安装兑换、心跳、任务租约获取、批量结果提交。任务包含 task ID、round ID、探测点 ID、地址版本、配置版本、目标 IP/地址族、检查配置、执行期限和租约标识。

探测点只能领取分配给自己的任务。租约过期可重新投递，任务结果以 task ID 幂等接收；旧租约、错误地址族、错误版本、吊销身份、跨节点提交不能改变健康状态。

Agent 有有界并发、有限本地结果缓存和指数退避。重试提交复用原 task ID；平台断连后不无限缓存、不继续执行过期任务。恢复联网后旧结果可留作历史，但不得触发当前轮换。

服务器分配轮次并以服务器时间判断截止期限；Agent 提供测量时间和耗时作为补充，不信任其时钟决定结果新鲜度。

## 8. 多探测点健康判定

IPv4/IPv6 各自选择探测组、检查配置和聚合规则。默认沿用检查间隔 15 秒、超时 3 秒、连续失败/成功各 3 轮；新建外部策略默认多数判定，用户必须至少选择一个对应地址族的探测点。

每轮的参与探测点集合在创建时固定。离线节点不能通过从分母消失来降低故障门槛。Agent 不支持该地址族时不能被配置到该组；配置变更创建新版本并重置连续计数。

令 M 为本轮配置的参与节点数、F 为有效失败数、S 为有效成功数。故障票数阈值 K 为：任意一个=1；多数=floor(M/2)+1；全部=M；至少 N 个=N；指定 Agent=只由该指定节点判定。最少有效结果数 Q 独立可配置，默认 M。

轮次截止后按以下规则聚合：

1. F+S < Q：unknown。
2. F >= K：failure。
3. S > M-K：success，即剩余未知结果即使全部失败也不会达到故障门槛。
4. 其余为 unknown。

unknown 不推进故障/恢复阈值，并重置连续轮数，防止把跨长时间失联的结果拼成连续失败。达到连续失败阈值才创建换址事件；达到连续成功阈值才认定候选地址通过。最终成功标准随故障规则变化，例如“全部失败才故障”允许部分探测点成功即恢复，界面展示这一含义。

每个轮次对计数最多贡献一次，不能把三个 Agent 的同时失败误算成连续三次失败。当前地址与每个候选地址分别计数；换址时旧结果不参与新地址判定。

探测结果有效期默认 60 秒；轮次截止时间至少覆盖拉取时间和检查超时，默认 10 秒。检查间隔必须不小于轮次执行窗口，同一目标/配置/探测点不重叠执行。配置超时变化时同步校验这些关系。

探测不足只暂停自动换址、继续调度和告警，不消耗换址次数。现有本地检查保持默认行为；选择外部判定的槽位不能被旧 Worker 单次本地结果覆盖。若用户明确选择本地探测点参与，则它作为独立一票进入同一聚合流程。

## 9. 轮换策略、状态与恢复

### 9.1 配置与默认值

| 配置 | 初始默认值 |
| --- | --- |
| 实例管理授权 | 关闭 |
| IPv4 / IPv6 自动轮换 | 分别关闭 |
| 允许停止再启动 | 关闭 |
| 单次故障最多尝试 | 3 次，可配置正整数 |
| 两次实际换址的最小间隔 | 60 秒，可调；厂商限流可要求更长等待 |
| 候选地址生效等待上限 | 120 秒，可调 |
| 单个候选地址探测窗口 | 180 秒，可调且能覆盖恢复阈值所需轮次 |
| 原有用户地址自动释放 | 关闭；单独显式授权 |

以上数值是本次文档提出的初始默认值，不是用户明确指定的数值。页面必须允许修改已承诺可配置的项目。

### 9.2 持久流程

事件依次经历：故障确认 → 等待锁/冷却 → 能力与授权复核 → 分配/改变地址 → 等待 AWS 生效 → 候选探测 → DNS 发布 → 清理 → 完成。

失败分为目标仍不通、探测不足、云 API 暂时失败、权限/配额问题、DNS 部分失败和清理失败，各有独立状态与下一步，不能全部变成“再次换 IP”。

一次实际申请候选或开始破坏性换址步骤计入一个尝试。先持久化尝试 ID，再调用 AWS；未知结果保持在该尝试内读取确认，不盲目启动下一个。明确未产生副作用的限流/权限拒绝不占实际换址次数。重试同一 API 或同一任务不能多扣次数。

达到上限后进入 exhausted 并锁存，不能被后续每轮失败反复创建新事件以绕过上限。继续监测；当前候选若自然达到成功阈值，可继续发布并关闭事件；之后发生新的独立故障才获得新预算。手动恢复显式创建新的预算段并记录审计。

同一实例的所有写步骤串行执行，IPv4/IPv6 使用不同事件和预算。任务带授权版本、地址版本、策略版本及锁 fencing 标识，过期任务不得发布 DNS 或再次写云端。

重启后从持久步骤恢复。AWS 异步操作通过返回的 operation/request/resource ID 和资源读取确认。没有原生幂等键的分配操作使用可检索的命名/标记及前后资源快照关联；若不能确定资源归属，暂停人工确认，不能继续分配制造泄漏。

API 超时先读取远端；限流按厂商要求退避；凭证失效或配额不足暂停并告警。轮换过程中有新配置或取消授权，停在下一次写入前，显示当前实际状态和残留资源。

### 9.3 清理与最后可用地址

记录每个地址是接入前已有，还是 MasterDNS 为某次尝试创建。默认只自动释放本系统创建、已不再使用且不存在 DNS 引用的候选资源；用户原有静态地址没有独立释放授权时保留。

旧地址可保留时，至少等所有受影响记录发布成功，并超过记录变更前的最大 TTL 加 60 秒宽限后再清理。清理前再次确认远端归属、附着关系和引用。若旧地址已被他人重新使用，跳过清理并告警。

原有地址不能保留的方式（例如动态地址重分配、Lightsail IPv6）在启用方式时明确说明影响。外部 DNS 缓存可能继续指向已失效的旧地址，本系统不承诺零中断或能找回已释放地址。

探测失败时只清理已被下一个候选替代且没有引用的临时候选；最后附着地址保留用于继续监测。预算耗尽时不额外释放最后一个地址或删除 DNS。原始地址仍保留且可恢复时提供人工恢复入口，默认先验证健康。

## 10. 数据与接口边界

新增持久实体：

- cloud_accounts、cloud_scan_scopes：身份、凭证引用、区域完整性及扫描错误。
- cloud_instances、cloud_interfaces、cloud_addresses：远端清单与实际状态。
- managed_address_slots、instance_authorizations：稳定地址来源、当前/候选版本、授权版本。
- probe_agents、probe_tokens、probe_groups：探测身份、能力和分组。
- probe_rounds、probe_tasks、probe_observations：轮次、租约、幂等结果及 unknown 原因。
- address_health_policies、address_health_states：地址族的权威聚合配置与状态。
- rotation_policies、rotation_incidents、rotation_attempts、rotation_steps：预算、冷却、远端步骤、恢复信息。
- managed_cloud_resources：创建归属、引用、保留/清理状态。

健康结果表补充任务/轮次/版本引用；原有布尔 success 只用于实际执行结果，unavailable/expired 保存在任务观察中，不伪造为 false。健康统计增加探测点/地址族维度，已有统计保留兼容读取。

云地址版本可被多个 endpoint 引用；现有 endpoint_addresses 的每节点/地址族 current/candidate 唯一约束继续成立。发布事务通过版本推进统一更新引用，避免单个 Pool 提前发布旧候选。

管理 API 使用 `/api/v1/cloud-accounts`、`cloud-instances`、`address-slots`、`probes`、`probe-groups`、`rotation-policies`、`rotations` 资源；Agent API 使用独立的 `/api/v1/probe-agent` 命名空间。所有写请求沿用当前幂等键、所有权校验、速率限制与审计方式。

轮换 Operation 复用现有操作历史展示和 DNS 子操作，但云步骤使用专属执行器；禁止把 DNS rollback 直接解释为释放/重新申请云 IP。策略回滚也不能重新认定已释放地址仍然可用。

## 11. 页面与告警

云账号页增加 AWS 接入，云实例页提供区域筛选、能力说明、授权勾选和 IPv4/IPv6 策略入口。账号/实例列表显示扫描不完整与权限错误。

DNS 编辑页提供云实例地址来源，展示同地址关联记录和管理冲突。健康页增加外部探测点、安装命令、在线状态、地址族能力、探测组、每轮投票与每个探测点的结果。

轮换详情展示事件原因、配置快照、尝试次数、当前 IP、候选 IP、已发布 IP、AWS 步骤、DNS 部分成功和清理状态。支持暂停、恢复、取消后续步骤及显式人工操作。

沿用 Webhook/Telegram，增加探测不足、轮换启动、复测成功/失败、次数耗尽、云权限/配额错误、DNS 发布失败、残留资源清理失败等事件。同一状态去重，持续故障采用已有提醒机制。

## 12. 验收与交付顺序

本设计分成三个交付阶段，但最终交付需要覆盖完整闭环：

1. 多云模型、AWS 只读发现和授权、能力展示、DNS 地址来源。
2. Go Agent、注册/租约协议、双栈探测、多节点聚合与管理页面。
3. AWS 自动换址、外部复测、DNS 发布、持久恢复、清理和通知。

必要自动化验证：

- AWS 适配契约：分页、多区域部分失败、IPv4/IPv6 能力、不可变 primary IPv6、限流和权限/配额错误。
- 授权：未勾选实例不能变更；撤销期间旧任务停止；跨用户、跨实例地址不能被申请绑定/释放流程误用。
- Agent：一次性 Token、吊销、租约重放、重复/乱序上报、地址族缺失、目标版本变化、时钟偏差、有限缓存。
- TCP/HTTP 本地双栈测试服务：超时、拒绝、TLS Host/SNI、正文匹配、Go 正则兼容、受控重定向。
- 判定表：任意/多数/全部/N/指定探测点、未知结果、分母固定、连续轮次、候选与旧地址隔离。
- 换址：相同候选返回、API 超时但已成功、进程在每个步骤中断、次数锁存、两种地址族同时故障、多个域名只换一次。
- DNS：跨厂商部分失败只重试 DNS、Pool 已切备用时不强行切回、漂移不会恢复已失效地址、旧 TTL 清理窗口。
- 资源生命周期：原有资源保护、临时资源有界清理、配额耗尽、清理失败可重试。
- 现有 build/typecheck/lint/test，Go test 与跨平台编译；界面验证桌面/移动端关键操作。

真实 AWS 测试仅在单独授权的测试实例、网卡和地址资源上执行。测试范围包括 EC2 动态 IPv4/EIP/可变 IPv6、Lightsail 静态 IPv4/符合条件的双栈 IPv6；无环境时明确标注未验收，不以 Fake 替代真实通过声明。

实现阶段应将探测结果应用逻辑从当前 HealthProcessor 中提取为共享入口，让本地和外部探测复用相同的版本验证与地址提升机制；不进行与本功能无关的全仓重构。
